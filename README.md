## О проекте и технический стек

Сайт написан на чистом **HTML5, CSS3 и Vanilla JavaScript** без сборщиков (`Webpack`, `Vite`), пакетных менеджеров (`npm`) и тяжёлых фреймворков. Благодаря этому проект открывается мгновенно, не требует установки зависимостей и стабильно держит 60 FPS даже на бюджетных смартфонах.

### Ключевые фичи
* **Генеративный ASCII-логотип на Canvas:** при загрузке страницы скрипт разбирает исходную картинку `assets/logo.png` попиксельно, подбирает символы по яркости, добавляет псевдообъём и проигрывает анимацию «проявления инея».
* **Оптимизация под мобильные устройства:** готовый ASCII-логотип склеивается в скрытый буфер (`logoCache`), плотность пикселей ограничена (`DPR <= 2`), а перерисовка главного экрана автоматически ставится на паузу, когда пользователь скроллит страницу вниз.
* **Атмосферный фон:** плавный снегопад из 220 частиц на отдельном фоновом `<canvas>` и виньетка.
* **ASCII-таймер обратного отсчёта:** отсчитывает дни, часы, минуты и секунды до старта выезда с короткой глитч-анимацией при смене цифр.
* **Адаптивная сетка контента:** блоки «О мероприятии», «Расписание дня», «Организаторы» и «Спикеры», корректно перестраивающиеся под десктоп, планшеты и встроенный браузер Telegram на телефонах.

## Шпаргалка: где и что редактировать

* **Поменять дату/время выезда (для таймера) или подкрутить графику** (плотность символов, скорость анимации, количество снежинок, цвета) → редактируем `js/config.js`.
* **Обновить тексты о мероприятии, поменять тайминги в расписании, добавить фото/описание организаторов и спикеров** → редактируем `index.html`.
* **Изменить шрифты, отступы, рамки карточек или поправить отображение на телефонах** → редактируем `css/style.css`.
* **Обновить сам логотип** → заменяем `assets/logo.png` (лучше использовать контрастное изображение на прозрачном или чёрном фоне).

## Как развернуть проект у себя (инструкция для команды)

### Шаг 1. Получить доступ к репозиторию
1. Передайте свой никнейм или email на GitHub администратору репозитория.
2. Примите приглашение в проект (придёт на почту и появится в уведомлениях на GitHub в разделе **Collaborators**).

### Шаг 2. Скачать (клонировать) проект на компьютер
Выберите удобный способ:
* **В IntelliJ IDEA:** верхнее меню `Git` → `Клонировать...` (`Clone...`) → вставьте ссылку `https://github.com/Arsikio/zima-studcom.git` → нажмите `Клонировать`.
* **В VS Code:** нажмите `Ctrl + Shift + P` → введите `Git: Clone` → вставьте ссылку `https://github.com/Arsikio/zima-studcom.git` и выберите папку на диске.
* **Через терминал / Git Bash:**
  ```bash
  git clone [https://github.com/Arsikio/zima-studcom.git](https://github.com/Arsikio/zima-studcom.git)
  ```

### Шаг 3. Запустить сайт локально для проверки
> ⚠️ **Важно:** не открывайте `index.html` двойным кликом как обычный файл (`file://...`). Из-за политики безопасности браузеров (CORS) функция чтения пикселей `getImageData()` блокируется при открытии с диска, и ASCII-логотип не отрисуется. Запускайте страницу только через локальный сервер:

* **В IntelliJ IDEA:** откройте `index.html`, наведите курсор в правый верхний угол окна редактора и нажмите на иконку любого браузера (Chrome, Edge, Яндекс). IDEA сама поднимет локальный сервер.
* **В VS Code:** установите расширение **Live Server**, откройте `index.html` и нажмите кнопку **Go Live** в правом нижнем углу экрана.

## Командная работа с Git и автодеплой

К репозиторию подключён **Continuous Deployment** на платформе **Netlify**.
* Основная рабочая ветка — **`master`**.
* Любые изменения, отправленные в `master`, **автоматически публикуются** на [zima-studcom.netlify.app](https://zima-studcom.netlify.app) через 10–15 секунд. Заливать файлы на хостинг вручную больше не нужно.

### Ежедневный цикл работы (чтобы не перезаписать код друг друга)

1. **Перед тем как начать менять код, всегда забирайте свежие правки команды:**
    * **IntelliJ IDEA:** нажмите `Ctrl + T` (или меню `Git` → `Обновить проект`).
    * **VS Code:** нажмите иконку синхронизации в левом нижнем углу или откройте меню `...` в панели Source Control → `Pull`.
    * **Терминал:**
      ```bash
      git pull origin master
      ```

2. **Внесите правки и проверьте их в браузере:**
    * Откройте инструменты разработчика (`F12` → иконка телефона/планшета в верхнем левом углу DevTools) и убедитесь, что вёрстка не поехала на узких экранах (360–430 px).

3. **Зафиксируйте и отправьте изменения на GitHub:**
    * **IntelliJ IDEA:** нажмите `Ctrl + Alt + K` (`Зафиксировать и отправить`), отметьте изменённые файлы, напишите понятный комментарий (например: `Добавил карточки спикеров первого дня`) и нажмите **Отправить (Push)**.
    * **VS Code:** перейдите на вкладку `Source Control` (`Ctrl + Shift + G`), нажмите `+` рядом с изменёнными файлами, введите сообщение коммита, нажмите `Commit`, а затем `Sync Changes`.
    * **Терминал:**
      ```bash
      git add .
      git commit -m "Краткое и понятное описание правок"
      git push origin master
      ```

### Работа над крупными задачами (через ветки)
Если вы берётесь за объёмную задачу (например, верстаете новый блок с нуля или меняете логику анимации), лучше делать это в отдельной ветке, чтобы не сломать рабочий сайт в процессе:
1. Создайте новую ветку от `master` (например, `feature/speakers-block`):
    * В IntelliJ IDEA: кликните по названию ветки `master` в правом нижнем углу → `Новая ветка` (`New Branch`).
    * В терминале: `git checkout -b feature/speakers-block`.
2. Пушьте изменения в эту ветку (`git push -u origin feature/speakers-block`). Netlify автоматически создаст **Deploy Preview** — отдельную временную ссылку, по которой вся команда сможет посмотреть ваш вариант вживую.
3. Когда всё готово и проверено, откройте **Pull Request** на GitHub и влейте ветку в `master`.

### Правила порядка в репозитории
* **Не добавляйте служебные файлы редакторов** (`.idea/`, `.vscode/`, `.DS_Store`) — они уже добавлены в `.gitignore`, не удаляйте их оттуда.
* **Пишите осмысленные сообщения коммитов:** вместо `fix` или `123` пишите `Обновил расписание вечерней программы` или `Поправил отступы в карточках на мобилке`.
* **Один блок — одна задача:** если двое одновременно правят один и тот же участок `index.html`, заранее договоритесь в чате, кто какой блок редактирует, чтобы избежать конфликтов при слиянии.
